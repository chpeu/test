# Session 13/12/2025 - Correctifs runtime (Phase 1B/1E/2D) + Boucle de vérification

## Contexte

Objectif de cette session:

- Identifier pourquoi le bot prenait peu de trades et valider que les phases déjà "implémentées" étaient bien actives en runtime.
- Corriger les écarts entre la documentation/implémentation et le comportement réel.
- Ajouter une boucle de vérification automatisée pour détecter rapidement les régressions (DB, API, persistance fichiers).

## Problèmes observés (avant correctifs)

- Phase 1B (Régime V2): méthodes présentes mais wiring runtime incomplet
  - ATR 5m non utilisé au runtime dans le calcul de régime.
  - Hystérésis non appliquée au runtime.
- Phase 1E (Auto-calibration): fonctionnalité implémentée mais pas déclenchée, et erreur d'import:
  - Erreur dans les logs: `No module named 'database.postgres_pool'`.
- Phase 2D (Auto-adaptation ML): contextes incomplets et persistance insuffisante
  - Contextes `UNKNOWN_UNKNOWN_*` pour le threshold optimizer.
  - Drift detector pas suffisamment persistant.
- Warnings ML:
  - sklearn: feature names manquants (cosmétique mais polluant)
  - joblib/loky: warning Windows sur détection des coeurs CPU

## Correctifs réalisés

### Phase 1B - Régime V2 (wiring runtime)

- `core/scanner.py`
  - Calcul et retour de `atr_percent_5m` (ATR 5 minutes en %).
- `core/market_regime_selector.py`
  - `check_regime()` accepte `atr_5m_values`.
  - Si `market_regime_v2_enabled=true`:
    - Calcul ATR via `calculate_combined_atr(atr_1m, atr_5m)`.
    - Lissage via `apply_smoothing()`.
    - Hystérésis via `should_change_regime()`.
- `main.py`
  - Transmission effective de `atr_5m_values` lors des appels à `check_regime()`.

Résultat attendu:

- `scan_logs.atr_pct_5m` rempli.
- `market_regime_history.detection_method = RULE_BASED_V2` quand `market_regime_v2_enabled=true`.

### Phase 1E - Auto-calibration + BTC indicator (activation runtime)

- Déclenchement périodique intégré dans `MarketRegimeSelector.check_regime()`:
  - Refresh BTC status (avec timeouts et gestion d'erreurs non bloquante).
  - Auto-calibration (cache 6h + cooldown de tentative).
- Correction de la calibration DB:
  - Suppression de l'usage de `database.postgres_pool` (module inexistant).
  - Exécution de la requête percentiles via `core.postgresql_datalogger.get_pg_datalogger()` (pool psycopg2 existant).

Résultat attendu:

- Plus d'erreur `database.postgres_pool`.
- Les seuils calibrés sont récupérables via `get_calibrated_thresholds()` et utilisés dans `determine_regime()` quand activés.

### Phase 2D - Auto-adaptation ML (threshold optimizer + drift detector)

- `core/ml/threshold_optimizer.py`
  - Le singleton recharge la config runtime (min/max/default/exploration/enabled) à chaque `get_threshold_optimizer()`.
  - Persistance corrigée:
    - Ne pas écraser `total_updates` après `_load_state()`.
    - Save à chaque update.
    - JSON écrit en UTF-8.
- `core/ml/drift_detector.py`
  - Le singleton recharge la config runtime (deltas/min_window/cooldown/enabled) à chaque `get_drift_detector()`.
- `api/routes/ml_config.py`
  - Les updates de config ML sont persistées dans `config_overrides.json`.
  - Propagation immédiate sur les singletons en mémoire.

Résultat attendu:

- Fichier `data/ml/threshold_optimizer_state.json` mis à jour dès qu'il y a des updates.
- Contextes stockés sous forme `REGIME_SESSION_HOURGROUP` (ex: `NORMAL_EUROPE_2`).
- Drift detector persiste après volume suffisant.

### Warnings ML (cosmétiques mais utiles)

- `optimization/predictor_optimized.py`
  - Passage d'un `pandas.DataFrame` (avec colonnes) à `predict_proba` même après scaling pour éviter le warning sklearn.
  - Définition de `LOKY_MAX_CPU_COUNT` sur Windows pour réduire le warning joblib/loky.

## Boucle de vérification runtime

Création:

- `verification/verify_runtime_loop.py`

Ce script vérifie à intervalle régulier:

- Backend API:
  - `/api/regime/status`
  - `/api/ml/status`
- PostgreSQL:
  - `scan_logs` (présence de `market_regime`, `atr_pct_1m`, `atr_pct_5m`)
  - `market_regime_history` (présence de `detection_method`, `atr_median`, `atr_smoothed`, etc.)
  - `trades` (présence du contexte d'entrée)
- Fichiers locaux:
  - `config_overrides.json`
  - `data/ml/threshold_optimizer_state.json`
  - `data/ml/drift_detector_state.json` (optionnel selon volume)
